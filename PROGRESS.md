## Сделано в вехе 1
- `drx-core::db`: схема ровно как Room v40 (из `crates/core/schema/room-40.json`); тест сверяет со схемой настоящего
  бэкапа — совпадает. Проверка версии: Created / Current / Older / Newer / Foreign.
- `drx-core::prefs`: кодек `settings.preferences_pb` (DataStore) без зависимостей; настоящий файл читается и
  пересобирается без потерь.
- `drx-core::shared_prefs`: кодек Android XML; все 41 файла настоящего бэкапа читаются и пересобираются без потерь.
- Тесты с настоящим бэкапом: переменные `DRX_TEST_SONG_DB`, `DRX_TEST_PREFS_PB`, `DRX_TEST_SHARED_PREFS_DIR`
  (бэкап лежит в `D:\dev\private\`, распаковывать во временную папку; в CI эти тесты пропускаются).
- Эксперимент по Mini (`spikes/`): размеры есть в `docs/PERFORMANCE.md`; память и CPU ещё не замерены
  (нужно окно — замерять, когда Apex не запущен: `scripts\measure.ps1 <exe>`).

- `drx-core::secrets`: сессии и ключ друзей при импорте уходят из открытых файлов в `secrets.dat` (DPAPI) и
  возвращаются в бэкап ПК, чтобы телефон их восстановил. Снимок перед импортом тоже зашифрован.
- `drx-core::http`: один клиент (rustls + ring, корни ОС), темп по хостам, одно короткое ожидание по Retry-After.
- `drx-core::store`: поток-писатель базы с событиями «изменились таблицы» (вместо опроса).
- `drx-transfer::backup`: просмотр бэкапа, импорт (снимок, без cookie YouTube, сброс курсоров чатов), создание бэкапа.
- `drx-app`: фасад — запуск ядра (Mini 2 потока), команды ImportBackup/CreateBackup, снимок состояния, живые списки
  (лайки, медиатека, плейлист, история) по диапазонам. Тест на настоящем бэкапе: 2403 лайка.

## Сделано в вехе 2 (звук, `drx-audio`)
- `decode`: symphonia 0.6 (MP4/WebM/Ogg/MP3/FLAC/WAV; AAC-LC, MP3, FLAC, Vorbis) + libopus; всегда стерео f32; seek;
  pre-skip Opus. libopus собирается cmake из Visual Studio (скрипт сборки сам добавляет путь).
- `source`: кэш-файл с потоком загрузки, разреженные диапазоны, перезапуск по Range при дальней перемотке.
- `hls`: плейлисты, AES-128 (IV из атрибута или номер сегмента), MPEG-TS → MP3/ADTS (порт TsAudioDemuxer.kt), fMP4.
- `resample`: FFT 44.1k → 48k, точная длина (gapless).
- `mixer` + `output` + `player`: голоса через кольцевые буферы, gapless-очередь, кроссфейд по кривым Android, пауза
  без щелчков, устройство отпускается через 5 с простоя и пересоздаётся при смене; часы воспроизведения.
  Проверено на реальном устройстве с громкостью 0.
- `dsp`: нормализация (clamp −15..+3 дБ), баланс, параметрический EQ (как BiquadFilter.kt, профили AutoEq, мягкий
  лимитер), детектор долгой тишины. Поведение описано в `docs/specs/audio.md`.
- `oggopus`: запись `.opus` без перекодирования с тегами и обложкой (для экспорта в Telegram).

## Сделано в вехе 4 (идёт)
- `drx-catalog`: общие модели и маршрутизация id как в Android (§2); Spotify (токен по TOTP, GraphQL, реестр хешей,
  лайки, плейлисты, альбомы, топы через `userTopContent`), Яндекс (аккаунт, лайки, плейлисты, альбомы, поиск),
  ВК (Моя музыка, плейлисты/альбомы с правилом «альбом или плейлист», треки по id, поиск). Всё проверено живыми
  тестами с сессиями из бэкапа (`DRX_TEST_PROFILE=<папка профиля>`; печатаются только числа).
- `drx-app::playback`: очередь, источник по URL (MP3 рядом с HLS ВК, иначе HLS), плеер открывается при первом
  воспроизведении, автопереход на следующий трек, prev/next/seek/volume, `NowPlaying` + часы.
- Mini: «ВК · Моя музыка» в медиатеке, двойной клик играет, нижняя панель с прогрессом (таймер только во время игры).
  `DRX_DEMO=<id списка>` — проверка без кликов (`vk:liked`, `sp:liked`, `ym:liked`, `sp:pl:<id>`…; громкость 0).
- `drx-app::accounts`: клиенты из хранилища секретов, основной аккаунт (`primaryMetadataSource`, иначе Spotify),
  вкладки аккаунтов (`accountTab_<SRC>`), «Любимые» каждого аккаунта и их плейлисты/альбомы в медиатеке
  (подгружаются в фоне), списки Spotify приходят постранично. Трек из лайков Spotify находится resolver'ом и играет.

## Сделано в вехе 5 (идёт)
- `drx-resolver::matcher`: порт `SpotifyMapper.selectBestMatch` со всеми воротами (название, исполнитель в обеих
  письменностях, кавер/ремикс, длительность 7/30 с, штраф за клип и live) и тестами из Android.
- `parallel`: одновременный опрос источников, режим AUTO с порогами Android (0,95 / 0,9 / 120 kbps / 1,2 с / 2,5 с / 14 с).
- `providers::vk`: поиск «Исполнитель Название» (30), строгий отбор (±8 с), старое имя группы, URL из выдачи или
  `audio.getById`. Живой тест: 5 из 5 первых лайков из бэкапа нашлись на ВК и играют.
- `providers::soundcloud`: client_id из скриптов веб-плеера, пропуск BLOCK/SNIP и DRM, официальные загрузки
  раньше перезаливов (≤0,85, ±3 с), правки/флипы отбрасываются; HLS AAC → ADTS (`drx-audio::fmp4`, порт
  Fmp4AdtsTransmuxer.kt), перемотка работает.
- Сохранённые совпадения: перед поиском плеер пробует трек ВК из самой медиатеки (`mfb:src:VK:…`), затем
  `audio_fallback_match` (общая с Android таблица — в бэкапе их 44 тыс.), найденное новым поиском записывается туда же.
- `providers::youtube`: visitorData из `sw.js_data`, поиск WEB_REMIX с фильтром «песни», поток через VISIONOS →
  ANDROID_VR 1.65.10 → TVHTML5 (готовые ссылки, без шифра), Opus в приоритете; перемотка за первый МиБ работает;
  `loudnessDb` → нормализация громкости (clamp −15..+3 дБ). Не сделано: подпись/n-параметр через JS (треки 18+), PoToken.
