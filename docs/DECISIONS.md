# DECISIONS

Решения по архитектуре и почему. Новое — сверху.

## 2026-11-14 — решения владельца после проверки брифа

**D-010. Один ключ Nostr на телефоне и ПК.** Ключ переносится в бэкапе (`shared_prefs/friends.xml`, `sk`) и должен быть в
бэкапе ПК. Чтобы устройства не перебивали друг друга, правила на стороне ПК (Android не меняем):
«слушает сейчас» ПК публикует только пока сам играет и не затирает статус телефона паузой; историю, лайки и статистику
публикует телефон. Резерв под синхронизацию устройств: пространство d-тегов `drxw:dev:<hash>`.

**D-011. Чаты восстанавливаются после восстановления бэкапа** — свои и чужие сообщения. Способ 1: из релеев — при импорте
сбросить курсоры чатов и подписаться и на входящие (`#p:[я]`), и на свои отправленные (`authors:[я]`), без ограничения
по давности. Способ 2, если релеи хранят мало: почтовый ящик на **бесплатном** Cloudflare (Workers + D1/KV) — хранит уже
зашифрованные NIP-04 события. Платить нельзя ни при каких условиях: только бесплатные лимиты, при их исчерпании —
мягкая деградация, не счёт.

**D-012. Cookie YouTube из бэкапа не переносятся** (одна cookie на двух устройствах может выкинуть оба). Spotify, Яндекс,
ВК переносятся с живой проверкой каждой сессии.

**D-013. Порядок вех — как в задании**, без спешки. В веху 0 добавлены эксперимент по бюджету Mini и проект фасада `app`;
пустая оболочка Full появляется вместе с оболочкой Mini.

## 2026-11-14 — подготовка (веха 0)

**Две редакции, два интерфейса, одно ядро.** Full — Tauri 2 + Svelte + TypeScript + Vite. Mini — нативный Rust без
веб-движка. Решение владельца, принято зная цену: каждый экран пишется дважды. Чтобы не дублировать логику, всё
состояние (очередь, медиатека, поиск, друзья, настройки) живёт в общих crates; интерфейсы только показывают состояние и
отправляют команды. Граница ядра и интерфейса уточняется в вехе 1.

**Имена crates с префиксом `drx-`.** Crate с именем `core` конфликтует со стандартным `core`.

**Папка сборки — `target/` внутри репозитория на D:.** В задании предложена `D:\dev\cargo-target` через
`.cargo/config.toml`, но абсолютный путь Windows в общем конфиге ломает сборку на Linux в CI. Репозиторий и так лежит на
D:, поэтому C: не затрагивается. Кэш скачанных библиотек (`CARGO_HOME`) и кэш npm переносит на D: скрипт
`scripts/build.ps1`.

**Сборки с ограничениями.** `scripts/build.ps1`: пока запущен Apex — приоритет Idle и 3 потока; пока работает VM для iOS —
BelowNormal и 6 потоков; иначе без ограничений; при нехватке памяти — до 2 потоков. Владелец играет и работает с VM
параллельно.

**Профиль `release-mini`:** `opt-level = "s"`, fat LTO, `codegen-units = 1`, `panic = "abort"`, `strip`. Проверить на
отсутствие заиканий звука (записать в PERFORMANCE.md); если `"s"` вредит декодированию — поднять оптимизацию только для
звуковых crates.

**Без Windows 7.** Стабильный Rust с 1.78 не собирает под Windows 7, нет SMTC, WebView2 закончился на версии 109.

**Без закреплённой версии Rust (`rust-toolchain.toml`).** Закрепление заставило бы rustup скачать второй набор
инструментов на почти полный диск C:. Минимальная версия указана в `rust-version` (1.85, нужна для edition 2024).

**Открытые решения (после замеров):**
- библиотека интерфейса Mini: Slint с программной отрисовкой (перерисовывает только изменённые области) против egui
  (перерисовывает всё окно; контекст видеокарты может занять 30–60 МБ) — замерить память и CPU в простое;
- шрифты Mini: встроенный латиница + кириллица, иероглифы из системных шрифтов Windows по требованию;
- экспорт AAC: Media Foundation на Windows; что на Linux — решить на этапе Linux.
